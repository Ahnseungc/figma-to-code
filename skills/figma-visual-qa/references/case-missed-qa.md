# 사례 — 토큰 QA는 통과했는데 화면은 틀렸다

실서비스 이벤트 홈 화면을 Figma MCP로 구현하고 3회 토큰 대조까지 통과했지만, 사람이 보자마자 찾은 문제 세 가지.

## 놓친 것

| 이슈 | 실제 | 에이전트가 한 일 |
|---|---|---|
| 82×32 고정 폭 칩의 "최대 300장" | Figma는 `whitespace-nowrap` 한 줄. 구현은 wrap돼 칩 안에서 2줄 | `scrollWidth === clientWidth` 로 PASS. 칩 크롭 없이 전체 페이지 캡처만 봄 |
| 카드의 티켓 일러스트 | Figma 합성과 해상도·패턴이 다름 | gap·shadow만 대조. "파일 있음, 티켓처럼 보임"으로 PASS |
| 금색 티켓의 **메탈릭 색** | 기준은 짙은 브론즈 금 avg ≈ `(173,124,23)` | MCP SVG와 바이트 동일 → PASS. 이후 blend를 피하려 평탄 그라데이션으로 재합성 → avg ≈ `(232,191,91)` 로 더 어긋남 |

## 왜 못 잡았나

1. **토큰 터널 비전** — 대조가 class·computed style(배경·gap·radius)에만 집중. 일러스트·라벨 줄 수는 체크리스트에 없었다.
2. **틀린 overflow 지표** — wrap은 가로 `scrollWidth` 를 늘리지 않는다.
3. **에셋 존재 = 일치라는 착각** — 파일이 있고 바이트가 같아도 렌더 맥락이 다르면 결과가 다르다.
4. **검은 캡처를 그냥 넘김** — 깊은 노드 `get_screenshot` 이 검게 나왔는데 부모 프레임으로 다시 찍지 않았다.
5. **SVG 바이트 동일 ≠ 픽셀 색 동일** — `mix-blend-mode: difference | overlay | color` 는 Figma 캔버스와 브라우저 `<img>` 격리 환경에서 다르게 합성된다.
6. **근사 재합성의 함정** — 헤드리스 브라우저로 평탄 SVG를 PNG로 뽑으면 해상도는 좋아져도 색 정본이 아니다.

## 색 대조 수치

| 샘플 | 기준 | 잘못된 재합성 | 판정 |
|---|---|---|---|
| 불투명 평균 | `(173,124,23)` | `(232,191,91)` | Δ ≈ +59/+67/+68 **FAIL** |
| 좌상단 | `(225,170,59)` | `(253,221,132)` | 과하게 밝음 |
| 우하단 | `(93,62,0)` | `(220,176,67)` | 암부 소실 |
| 중앙 | `(190,134,22)` | `(189,141,42)` | 비슷해도 전체 톤 불일치 |

**수정:** 기준 이미지를 투명 배경으로 크롭해 에셋으로 사용 → 평균 `(173,123,23)` 로 재일치.

## 교훈

- 칩·라벨은 **크롭해서** 본다. 지표는 텍스트 높이.
- 일러스트는 **같은 크롭을 나란히** 본다.
- 금속성·블렌드 색은 **평균 RGB로 게이트**한다.
